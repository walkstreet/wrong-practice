# 编组与分层统计（规划档）

- 状态：编组与按组分配已落地；分层统计看板（独立页、组间对比）未开工
- 记录日期：2026-09-01
- 来源：产品后续意向（先编组；任务可按组分配；再做统计）

学生页已支持按机构/老师/编组筛选，并在当前范围内显示错误率与能力排名。独立统计看板仍按第 5 节后续做。

实现时以本文为范围，细节再开任务拆。

---

## 1. 当前结构

当前学生归属只有两层：

```
机构 organization
  └── 老师 teacher（学生.teacher_id）
        └── 学生 student
```

- 学生一人只属于一位老师（`users.teacher_id`），机构管理员可改所属老师。
- **已有编组实体**（`student_groups` / `student_group_members`）。花名册、画像里的「班级」在未选编组时仍表示「当前角色能看到的全部学生」的均值。
  - 教师：自己名下学生
  - 机构管理员：本机构学生
  - 超管：全平台学生
- 已有个人统计：作答次数、正确率、知识点短板、能力轴（题型大类雷达），老师画像页会对比「班级」均值。
- 学生端明确不展示同学数据和排名（见「我的短板」）。

相关入口：

- 花名册 `GET /api/v1/admin/students/roster` → `/students`
- 画像 `GET /api/v1/admin/students/{id}/portrait` → `/students/:id`
- 学生自己 `GET /api/v1/me/portrait`（无对比、无排名）
- 任务分配 `POST /api/v1/admin/assignments/{id}/assign-users`：可传 `user_ids` 和/或 `group_ids`；管理台可先选编组再增减个人

---

## 2. 目标顺序

1. **老师对学生编组**（先做管理能力）
2. **安排任务支持按组分配**（与按人勾选并存）
3. **再做统计**：编组统计 + 该范围下全部学生统计
4. 统计产出至少包括 **错误率** 和 **学生能力排名**
5. 统计可按层级下钻：**机构 → 老师 → 该老师的编组**
6. **超管能看到全部统计**（跨机构）

---

## 3. 编组（第一步）

编组是老师名下的学生子集，用来上课、布置和对照，不是改 `teacher_id` 的第二套归属。

建议约束（实现前可再确认）：

| 项 | 建议 |
| --- | --- |
| 归属 | 编组属于一位老师，且落在该老师所在机构 |
| 成员 | 只能加入该老师名下的学生 |
| 一人多组 | 允许（例如「阅读强化」和「语法班」可重叠） |
| 未编组 | 允许；「全部学生」统计仍覆盖该老师名下所有人，不丢未入组的 |
| 谁可管 | 老师管自己的组；机构管理员可看/协调本机构；超管可看全部 |
| 任务 | 编组落地后，布置任务必须能按组一键分配，见第 4 节 |

建议实体（仅示意，表名实现时再定）：

- `student_groups`：id、name、teacher_id、organization_id、created_at
- `student_group_members`：group_id、user_id（学生）、unique(group_id, user_id)

机构管理员改学生所属老师时：该生应从**原老师**的编组里移除（或标记失效），避免跨老师残留。

---

## 4. 任务按组分配

编组的直接用途之一是布置任务。现有分配只认学生 id，组上线后分配入口要同时支持：

- **按组**：选一个或多个自己的编组，把组内当前成员一并分到该任务
- **按人**：继续多选学生（未入组、或只要组里一部分人）
- **混合**：先选组，再加减个人

### 4.1 落库方式

任务实例仍是「一人一条」`user_assignments`，不要做成「任务绑死某个组、成员变动自动进退」。

建议行为：

| 场景 | 建议 |
| --- | --- |
| 按组点分配 | 展开为**当下**组内启用学生，写入 `user_assignments`；已在任务里的人跳过（与现逻辑一致） |
| 分配后再有人进组 | **不**自动拿到该任务；需要老师再按组/按人分一次 |
| 分配后有人离组 | **不**自动撤销已发任务；作答权仍看 `user_assignments` |
| 空组 | 提示组内没有可分配学生，不创建空分配 |
| 权限 | 只能用自己可见的组；组员必须仍是该老师名下、启用中的学生 |
| 关闭的任务 | 与现在一样，不可再分配 |

可选：在分配记录里记下「这次是从哪些组展开的」（审计/回显「当时按阅读班分配」），不影响判分和提交列表。不做也可以，提交列表仍按学生。

管理台：分配弹窗在学生多选之外增加编组多选；确认后人数预览（组展开去重 + 已分配跳过）。

### 4.2 和统计的关系

按组分配只决定谁收到任务。组的错误率、能力排名仍按**当前组成员**的作答聚合，不要求「必须做过同一份按组任务」才进组统计。

## 5. 统计（编组落地后）

### 5.1 维度（从机构到老师的编组）

```
平台（仅超管）
  └── 机构
        └── 老师
              ├── 该老师全部学生
              └── 该老师的某个编组
```

同一套指标在每一层都能算；下一层是上一层的子集。超管从机构进到老师，再进到编组；机构管理员从本机构老师进到编组；老师默认看自己的全部学生和自己的组。

### 5.2 可见范围

| 角色 | 能看的统计 |
| --- | --- |
| 超管 | 全平台；可按机构、老师、编组下钻 |
| 机构管理员 | 本机构；可按本机构老师、编组下钻 |
| 教师 | 自己名下全部学生 + 自己的编组 |
| 学生 | 仍只看自己；不看同学排名、不看组排名（与现「我的短板」一致） |

超管「都能看到」指管理侧统计，不改变学生端隐私边界。

### 5.3 指标（至少）

口径沿用现有作答数据（`user_answers.is_correct` 等），不要另起一套对错定义。

**错误率**

- 错误率 = 错题次数 / 作答次数（与现正确率互为补：正确率 = 1 − 错误率）
- 可先给整体，再按题型大类、知识点拆（与画像轴、短板一致）
- 样本不足时沿用画像规则（次数不够则标「数据不足」，不硬排名）

**能力排名**

- 对象：范围内学生（某编组，或某老师/机构的「全部学生」）
- 主序建议：综合正确率（作答次数达标者）；同分再比作答量或最弱知识点
- 能力轴可作并列展示（选择 / 语篇 / 语言运用等），排名是否按轴拆开实现时再定
- 花名册现有的滞后 / 关注 / 稳定 / 数据不足，可继续当筛选项，不当成排名分数本身

每层汇总建议同时给出：

- 范围人数、作答人数、平均错误率（或平均正确率，界面统一一种）
- 学生列表（可按错误率或能力名次排序）
- 编组之间对比（同一老师下各组均错率）——有编组之后再做

### 5.4 和现有「班级」文案

编组上线后，画像里的对比基准应可切换：

- 默认：所在编组（若只属一组）或老师名下全部学生
- 多组时：老师选「对比哪个组」；超管/机构管理员沿用当前下钻范围

在此之前，代码和文案里的「班级」继续表示「当前可见学生集合」，不要先改名造成误解。

## 6. 建议实现顺序

1. 编组 CRUD + 成员管理 + 改所属老师时清理组籍
2. 任务分配支持按组（可与按人混合）；花名册可按组筛选
3. 统计页：老师看「全部学生 / 按组」；错误率 + 能力排名
4. 机构管理员、超管下钻：机构 → 老师 → 编组
5. 组间对比看板（更后）

---

## 7. 实现时不要做的

- 不要用编组替换 `teacher_id`（归属和教学分组是两件事）
- 不要让组员变动自动增删已有 `user_assignments`（分配按当时成员快照）
- 不要拿掉按人分配；按组是快捷方式，不是唯一入口
- 不要让学生看到组内排名
- 不要让教师看到其他老师的组或跨机构数据
- 不要在编组未落地前，把现有「班级均值」改成假的分组统计
